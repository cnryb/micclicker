# MicClicker 总体设计

无线语音输入 + 快捷键桥接设备：AI Passport（ESP32-C3）经 ESP-NOW 连接 ESP32-S3，为电脑提供免驱的标准 USB 麦克风 + HID 键盘。

> 本文用于确认系统架构、关键设计基线和验证路径，不代替原理图、详细协议或施工级固件设计。标注“待验证”的硬件参数和第三方库能力，须在对应开发阶段开始前确认。

## 1. 目标与范围

制作一套一对一无线桥接设备：

1. AI Passport（ESP32-C3）采集语音，经无线链路传到 ESP32-S3；S3 作为电脑的**标准 USB 麦克风**，供 ASR 应用使用。
2. AI Passport 的 UP / DOWN / OK 按键经 S3 转换为**标准 USB HID 键盘事件**。
3. 正常使用无需安装桥接软件或专用驱动；配套提供按需运行的配置工具，用于状态查看、配对管理和快捷键配置，不参与音频或 HID 转发。ASR 应用本身、系统麦克风权限和输入设备选择不在此范围内。

首版范围限定为：一个发送端、一个接收端、单向音频流和键盘输入；不包含扬声器、多发送端或后台全局热键。普通 HID 事件只发送给系统当前焦点，不能保证后台 ASR 应用收到快捷键。

## 2. 硬件与工具链基线

| 角色 | 硬件 | 职责 |
| :--- | :--- | :--- |
| 发送端 | AI Passport / ESP32-C3 | 麦克风采集、按键检测、G.722 编码、ESP-NOW 发送 |
| 接收端 | ESP32-S3 开发板 | ESP-NOW 接收、音频解码与缓冲、USB 麦克风 + HID 键盘 |
| 电脑 | Windows / macOS / Linux | 使用系统 UAC/HID 驱动，运行录音或 ASR 应用 |

以下项目是硬件相关编码的前置条件：

| 待确认项 | 必须固化的内容 |
| :--- | :--- |

| ADC 电阻梯 | 无键电平、三键电压区间、电阻误差、消抖与迟滞参数；不能仅凭 GPIO0 推断 |

## 3. 总体架构与固定参数

```text
AI Passport (ESP32-C3)
  麦克风 → PCM → G.722 ─┐
                        ├→ ESP-NOW → ESP32-S3
  按键 → 按下/释放事件 ─┘                 ├→ 解码/缓冲/同步 → USB 麦克风
                                         ├→ 映射/释放管理   → USB HID 键盘
                                         └→ 状态/配置管理   → USB 配置 HID
电脑：系统录音或 ASR 应用 + 当前焦点应用 + 按需配置工具
```

| 项目 | 设计基线 |
| :--- | :--- |
| 音频 | 16 kHz、16-bit 有符号小端 PCM、单声道；每帧 20 ms，即 320 个采样 |
| 编码 | G.722 **64 kbit/s**，160 字节/20 ms；PCMFlow722 仅为候选实现，须验证接口、许可证和标准测试向量 |
| 无线 | 按 ESP-NOW v1.0 的 250 字节兼容上限设计，不经过 Wi-Fi 路由器 |
| USB | 原生 USB 复合设备：UAC 麦克风 + HID 键盘 + 独立 vendor-defined HID 配置接口；首版不增加 CDC/MIDI |
| 拓扑 | 音频 C3 → S3；按键事件 C3 → S3，ACK、心跳/状态和配对控制按协议传输 |

选择编码是为了降低空口占用并保持“一帧一包”，不是因为 PCM 无法分片传输。首版不追求 48 kHz 或极限传输距离。

## 4. 无线连接与数据包

### 4.1 连接、配对与安全

- 两端先初始化 Wi-Fi STA（首版不连接 AP），配置相同的 2.4 GHz 信道，再初始化 ESP-NOW；具体信道由现场干扰测试确定并写入配置。
- 两端通过物理操作在限定时间窗内进入配对，双向发现并确认后记录对端 MAC、信道、接口和配对标识到 NVS，再切换为单播；正常重连不清除绑定，解除绑定和恢复默认必须显式执行。
- 广播仅用于无敏感数据的发现或连通性调试，不用于正式语音和按键流量。
- 联调阶段的明文模式仅限受控环境；实际使用应启用加密单播，并明确 LMK/PMK 配置与存储方式。MAC 地址本身不构成身份认证。
- 两端用 LED 至少区分未配对、配对中、已配对但离线和已连接；S3 另示 USB 状态。
- 以心跳维护链路状态，S3 汇总两端状态供配置工具查询。掉线后停止无效音频排队并自动重连；S3 重启、会话变化或链路超时时，必须释放全部 HID 按键。

### 4.2 应用数据包基线

公共字段均采用小端序；接收端丢弃未知版本、未知类型和长度不符的包。

| 字段 | 长度 | 说明 |
| :--- | ---: | :--- |
| `version` | 1 B | 当前为 1 |
| `type` | 1 B | `0x01` 音频、`0x02` 按键、`0x03` 按键 ACK；心跳/状态和配对等控制类型后续定义 |
| `session` | 2 B | C3 启动时生成的新会话 ID，ACK 回送原值，用于隔离上次会话的延迟包 |
| `seq` | 4 B | 各类型独立递增；音频按帧编号，按键按事件编号，重传不改变事件序号 |

| 类型 | 负载 | 总长度 |
| :--- | :--- | ---: |
| 音频 | 160 B G.722 数据；固定一帧一包 | 168 B |
| 按键 | `key_id` 1 B + `event` 1 B（按下/释放） | 10 B |
| 按键 ACK | 被确认的按键事件 `seq`，4 B | 12 B |

音频不因跳号而重传迟到帧。按键事件以相同序号重传，直到收到 ACK 或达到重试上限；S3 按序号去重。发送队列允许按键和 ACK 排在音频之前，但不能抢占已在发送的包；拥塞时丢弃最旧音频帧并计数，禁止无界积压。

## 5. 端侧设计

### 5.1 音频与实时处理

- C3 将麦克风原始采样转换为 16-bit PCM 后编码；若硬件输出 24/32-bit 数据，须明确缩放、截位、字节序和增益处理。
- S3 解码后进入有界环形缓冲。初始可以 60 ms（3 帧）作为联调起点，再按实测延迟和丢包调整。
- 音频按序号去重并识别缺口；缺口使用解码器 PLC 或静音补偿，欠载输出静音，溢出丢弃最旧帧，均记录统计值。
- C3 采样时钟与 USB 主机时钟长期存在漂移。基线方案是根据缓冲水位进行轻量重采样；若改用 USB 自适应同步，须先验证所选协议栈和主机的支持。
- ESP-NOW 和 USB 回调只投递数据，不执行编解码或阻塞等待；任务优先级、队列长度、CPU/RAM 和看门狗情况纳入测试记录。

### 5.2 按键与 HID

首版默认映射如下；映射保存于 S3 NVS，由配置工具读取、修改和恢复默认。修改映射前执行 all-keys-up，非法配置不得写入。

| 物理按键 | 默认 HID 输出 | 说明 |
| :--- | :--- | :--- |
| UP | Left Alt | 按下/释放成对发送；仅在目标应用支持单修饰键时有实际作用 |
| DOWN | 保留 | 首版不发送键值 |
| OK | Enter | 按下/释放成对发送 |

C3 只对去抖后的状态变化生成事件，不依赖电脑端自动重复。S3 维护当前按键状态；全部释放时发送全零键盘报告，掉线、超时、USB 重置和新会话均执行 all-keys-up。验收 Alt 时检查键事件及目标应用行为，不以“必然出现菜单动作”为标准。

### 5.3 USB 复合设备

- S3 首选 ESP-IDF + TinyUSB；EspUsbDevice 仅作备选。Audio + 键盘 HID + 配置 HID 的组合能力、UAC 版本和维护状态必须通过第 2 阶段的 USB 原型验证，不能仅凭库名假定。
- 按目标 OS 确定 UAC1/UAC2，并固化 AudioControl/AudioStreaming、IAD、采样格式、HID 报告描述符、VID/PID、产品字符串和序列号。
- 基线端点为音频等步 IN + 键盘 HID 中断 IN，配置 HID 的报告和端点按原型确定；若同步方案或 HID LED 需要额外端点，再根据所选协议栈复核，不预留无用接口。
- 配置工具仅通过独立 HID 配置接口访问状态和配置，不复用键盘报告；目标 OS 的访问权限纳入原型验证。
- 正式固件不增加 CDC；调试输出使用独立的 UART 方案，避免与 USB 设备功能冲突。当前 S3 板卡自带 CH343 UART 桥（丝印 `COM` 口）可直接承担该通道，无需外接 USB-TTL；但芯片侧 UART0 引脚（默认 GPIO43/44）是否引出需对着实物确认（见 [hardware-s3.md](hardware-s3.md)）。
- 每个目标 OS 都要验证枚举、麦克风权限、设备选择、热插拔和休眠恢复；UAC2 还需记录对应的 Windows 最低版本要求。

## 6. 分步实施

| 阶段 | 内容 | 通过后再进入下一步的条件 |
| :--- | :--- | :--- |
| 1. 硬件与依赖确认 | 锁定第 2 节参数；验证麦克风、ADC 按键、状态/配对控件和原生 USB | 获得可复现的引脚、阈值、BSP 和构建基线 |
| 2. USB 原型 | S3 输出已知 PCM/正弦波，同时发送成对 HID 按下/释放并验证配置 HID | 目标电脑同时识别并实际录音、接收键事件，配置工具可通信 |
| 3. 编码与无线分测 | G.722 标准向量对拍；用合成数据测试 ESP-NOW 丢包、乱序、吞吐、配对和心跳 | 编解码正确，配对可持久化，无线统计可记录，不依赖 USB 联调排错 |
| 4. 音频全链路 | C3 采集编码，S3 解码、缓冲并输出 USB 音频 | 连续录音和 ASR 可用，无持续断流或缓冲失控 |
| 5. 按键与故障联调 | 加入运行时映射、ACK、去重和 all-keys-up，注入丢包、掉线、重启 | 状态显示正确，音频与按键并发正常，无卡键，链路可恢复 |

## 7. 首版建议验收基线

| 类别 | 最低检查项 |
| :--- | :--- |
| 音频 | 每个目标 OS 连续录音至少 30 分钟，无复位、持续断流或异常重新枚举；记录丢包、PLC、欠载、溢出和端到端延迟 |
| 按键 | 至少 1000 次按下/释放及 20 次强制断链，无卡键；记录丢失、重复和恢复时间 |
| 状态与配置 | LED 状态正确；配置工具可读取状态、修改并持久化映射，解除配对后需重新配对 |
| USB | 每个目标 OS 完成热插拔和休眠/唤醒测试，无需重装驱动；音频、键盘 HID 与配置 HID 同时工作 |
| 无线 | 记录测试信道、距离、遮挡、干扰、丢包率和重连时间；不预设“20–30 米稳定”等未实测结论 |
| 资源 | 无看门狗复位、内存持续下降或无界队列；保留 CPU、内存和队列高水位记录 |

延迟统一按“C3 完成一帧采集至主机应用取得对应音频”测量，并单独列出无线、缓冲和 USB 耗时。ASR 效果应与同环境的有线麦克风基线比较，不只判断“能录音”。
