# MicClicker 实施路线图

> 生成时间：2026-11-16（Asia/Shanghai）更新。基线提交 `f82699e feat(audio): 打通第 4 阶段音频全链路`；按键链路（A1–A5、A8）已实现；**macOS 第 5 阶段验收（100 次按键、20 次强制断链、并发判分）已于 2026-11-16 补完**；工作线 B/C 与 `map_change` 宿主入口仍未开始。

## 1. 一句话结论

音频方向（第 1–4 阶段）已经端到端打通并有 30 分钟真机判分记录；**按键方向（第 5 阶段）已于 2026-11-15 实现，macOS 验收于 2026-11-16 补完**（100 次按键、20 次强制断链、音频+按键并发均 PASS，见 `firmware/tests/key_link/README.md` 4.2）。当前固件在 macOS 上「能录音、能配对、能重连、按键能出成对 HID 事件且断链不卡键」。还缺：映射的配置命令集（工作线 C1，含 `map_change`）、状态显示和跨平台验收（工作线 B）。

下一步（见第 5 节）进入**工作线 C**（先做配置 HID 命令集 C1，再做最小跨平台宿主）；工作线 B 可并行。

### 4.4 一处待查异常（本次整理发现，尚未定位）

`C3_AUDIO: STATUS` 的 `late` 计数在真机日志里稳定地按比例增长，但 S3 侧同期 `gap=0 loss=0`，两端速率也一致（50.02 vs 50.01 fps）：

| 运行 | 窗口内 `late / captured` | 说明 |
| :--- | ---: | :--- |
| 30 分钟录音（`.tmp/stage4-20261115-1030/c3_30min.log`） | **27 999 / 83 997 = 33.3%** | 恰好 1/3 |
| 60 秒联调（`.tmp/joint-60s-20261115-112834/c3.log`） | 287 / 3 009 = 9.5% | |
| 三轮 30–44 秒联调 | 9.7% / 11.6% / 10.5% | 约 1/10 |

两点观察，都是数值事实而非结论：

1. 30 分钟那轮回 **恰好 1/3**（27 999 / 83 997），像是固定节拍图案被门槛切中；
2. 但短窗口不是固定的 1/10，而是 9.5% / 9.7% / 11.6% / 10.5% 四个不同值，**不像**同一个周期图案——这正是不该急着下结论的原因。

判据在 `firmware/c3/main/audio_task.c:178`：相邻两帧**起点**间隔 > 1.5 个帧周期（30 ms）就计一次。`check.sh` 不判这一项（它只读 S3 的 `late`），所以这些运行都显示 PASS。

**尚未定位原因。以下是候选机制，全部属于待验证假设，不是结论：**

`capture.c` 初始化时把 I2S 配成立体声双 slot（`.slot_mode = I2S_SLOT_MODE_STEREO`），但 `esp_codec_dev_open()` 会按 `channel = 1` 重配成单 slot（`audio_codec_data_i2s.c` 的 `set_drv_fs()`，mono 时 `slot_mask` 被收窄）。DMA 描述符是 240 帧/个（`dma_frame_num = 240`，注释按 16 kHz 折成 15 ms），而一帧要 320 样本，一次 `esp_codec_dev_read()` 要凑满 320 才返回（`MIC_CAPTURE_CHUNK_SAMPLES * 8 = 1280 > 320`，循环只跑一次）。**320 与 240 不成整数比**：若读只在某个内部缓冲边界完成，相邻帧起点间隔就可能呈 15 / 15 / 30 ms 之类的重复图案——平均仍是 20 ms（所以平均帧率精确 50.00），而约 1/3 的间隔会触到 30 ms 门槛。这与 30 分钟那轮回 **恰好 1/3** 吻合。

但这条假设**解释不了短窗口的约 1/10**（287/3 009、143/1 479、255/2 193、225/2 142）。也就是说至少还有一个未识别的因素，可能是 `esp_codec_dev_read()` 的返回时机与描述符并非简单对齐，也可能是运行时读路径不总在同一粒度完成。**在这两处数字能被同一个机制解释之前，不要把这个计数当成「C3 节拍抖动」的证据，也不要用它反推无线或缓冲行为。**

**处理建议**：在接入按键前花半天查清——用 GPIO 翻转 + 逻辑分析仪，或 `esp_timer` 微秒级直方图，直接测帧起点间隔分布，看它是否真呈周期图案；同时核对 `esp_codec_dev` 实际采用的 slot 配置（开机会打印 `STD: RX ... slot_mode=...`）。要么改用「帧起点相对理想网格的累计偏差」这一不受读粒度影响的口径，要么证明它无关紧要并写进 README。否则第 5 阶段的按键重传时序分析会建立在一个含义不明的指标上。

## 5. 下一步：三条工作线

### 5.1 工作线 A（**优先**）：第 5 阶段按键链路 + 链路存活

目标：**按键能用、断链不卡键**。这条线同时补齐三个现在完全缺失的运行时机制，所以排在最前。

| # | 任务 | 完成判据 |
| :--- | :--- | :--- |
| A0 | 查清 4.4 的 `late` 口径 | 指标含义确定并写入 `tests/audio_link/README.md`，或改为可解释的新计数 |
| A1 | C3 按键采集：复用 `board.h` 的四态窗口，独立去抖任务，只产出去抖后的按下/释放事件 | 主机侧新增按键去抖/窗口分类测试；真机按 100 次无重复、无丢失事件 |
| A2 | C3 按键发送：`mic_link_build_key` → 与音频共用发送路径（按键可插队，不抢占在发包），未 ACK 时**同 seq** 重传至上限 | 日志中 `key_dup` 等于注入的重传次数，`key_rx` 等于真实事件数 |
| A3 | S3 按键接收：解析 KEY → 按 seq 去重 → 查映射表 → 生成 HID 报告；维护完整按键状态 | `keyboard HID` 报告成对、`all-keys-up` 时全零 |
| A4 | 运行时映射表：默认 UP=Right Alt、DOWN=保留、OK=Enter，存 S3 NVS，写入前校验 | 非法映射被拒且不落盘；改映射前先 all-keys-up |
| A5 | 心跳与存活：C3 每秒发 heartbeat，S3 用 `echo_seq` 回复并上报计数；两端各自判超时 | 拔掉 C3 电源后 3 秒内出现明确的超时日志，**且所有按键已释放** |
| A6 | all-keys-up 触发点补齐：USB attach/detach/suspend/resume 已挂在 `usb_prototype.c`，本阶段要**新增**链路超时、新会话、S3 重启、映射修改前四个触发点，并让释放动作与「无线按键状态」一致 | 逐项故障注入，每项都有对应日志与全零报告 |
| A7 | 延迟打点：C3 帧头记采集完成时刻，S3 记送到端点时刻（估算即可，不引入时钟同步） | 能给出无线+缓冲+USB 的粗略分解，量级与 60 ms 目标水位自洽 |
| A8 | 判分脚本 `firmware/tests/key_link/check.sh`（仿 `audio_link/check.sh`）与实测记录 | 一条命令给出 PASS/FAIL，覆盖 A2/A3/A6 的可观测指标 |

**退出条件**（DESIGN 第 6 节第 5 阶段）：状态显示正确、音频与按键并发正常、无卡键、链路可恢复。

关键复用点：`components/link_proto/` 已有按键帧编解码、独立序号、按 seq 去重，且被 141 项主机侧断言覆盖；`components/link_probe/` 里有现成的「重传直到 ACK」实现（探针态）可以直接搬到产品态，但**不要**把探针整体拉进产品镜像（探针每次启动擦 NVS）。

### 5.2 工作线 B：跨平台与真实场景验收

与 A 并行推进（不共享代码），但结论必须落在同一套判分脚本上。

1. **Windows 先做**（UAC2 在 Windows 的最低版本要求决定是否要退到 UAC1，这是有可能推翻 S3 描述符的决定，越早知道越好）。
2. 同一台机器跑 `check.sh` 的 30 分钟判分 + 录到真实语音，作为平台基线。
3. 热插拔、休眠恢复、异常 SET_CUR 采样率的行为记录。
4. 距离/穿墙/干扰：固定信道与距离档位，复用 `tests/espnow/check.sh` 与 `tests/audio_link/check.sh`。
5. ASR 基线：与有线麦同脚本对比。

### 5.3 工作线 C：配置工具与产品化

依赖 A4（映射接口）与 A5（状态字段），所以排在 A 之后。

1. 先在 S3 配置 HID 里扩出「读映射 / 写映射 / 读链路状态 / 发起配对 / 解除绑定」的命令集，保持 64 B 报告与向后兼容的布局（现有 0–47 字节不能改语义，只能追加）。
2. 选型一个最小跨平台宿主（macOS/Linux 先，Windows 后），只做按需运行的状态查看与配置，不做常驻转发。
3. 产品标识：`303a:4014` 是原型 PID，正式 VID/PID、产品字符串、序列号策略需要确定（属用户决策，见第 6 节）。
4. 状态显示：C3 屏幕/背光四态（未配对/配对中/离线/已连接），引脚已在 `board.h`，需要挑一个轻量 ST7789 驱动并验证反色（`MIC_BOARD_LCD_INVERT_COLOR=1`）与人眼观感。
