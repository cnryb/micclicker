# 音频全链路真机验收（第 4 阶段）

本目录是 [DESIGN.md](../../../docs/DESIGN.md) 第 4 阶段的判分工具与实测记录。它判的是**两端真机经无线链路录音**这条路径，不是单端自检。

## 1. 被测路径

```
C3 (AI Passport)                                        S3 (ESP32-S3-N16R8)
ES8311 + I2S                                           UAC2 麦克风端点
16 kHz / 16 bit / 单声道                               16 kHz / 16 bit / 单声道
   │                                                          ▲
   └─ 320 样本/20 ms ─ G.722 160 B ─ 一帧一包 ESP-NOW 加密单播 ─┘
                                        └─ 解码 ─ 自适应环形缓冲
```

两端均为产品固件（非探针）：`./firmware/build.sh c3` 与 `./firmware/build.sh s3`。

## 2. 判分脚本

```bash
./firmware/tests/audio_link/check.sh <C3 console log> <S3 console log> [期望秒数]
```

脚本只读两端每秒一条的 `STATUS` 行，判以下几项：

| 检查 | 判据 | 理由 |
| :--- | :--- | :--- |
| 发送帧率 | 50.00 fps ±2% | 320 样本/20 ms 是设计基线，偏差意味着采集或节拍错 |
| 采集/编码错误 | 必须 0 | 任何非零都说明 codec 或编码器有问题 |
| 发送失败率 | ≤ 0.5% | ESP-NOW 队列瞬时满会导致拒发，发送端用同一序号重试；大量失败说明无线跟不上 50 fps |
| 送达率 | ≥ 99% | `sent / captured` |
| 解码错误 | 必须 0 | 零丢包时不应出现 |
| 有效丢包 | ≤ 0.1%（`gap − late`） | 见 [protocol.md](../../../docs/protocol.md) 3.4 |
| 环形缓冲溢出 | 必须 0（录制中） | 溢出＝端点没被排空，可听为断裂 |
| 欠载 | ≤ 2% | 起步预热应为 0；持续欠载说明链路撑不住 50 fps |
| 缓冲高水位 | ≤ 200 ms | 控制器失效会让缓冲贴到容量或贴到 0 |

`check.sh` 的阈值就是第 7 节验收基线里“无持续断流或缓冲失控”的可执行版本。

## 3. 实测记录

### 3.1 链路连通（2026-11-15）

条件：两块板卡各自接 USB，同一台 macOS 主机；ESP-NOW 信道 1，两板相距约 1 米，直视；未做屏蔽。

| 项 | 结果 |
| :--- | :--- |
| 配对 | C3 首启无绑定 → 广播配对请求；S3 未绑定时常驻监听 → 双方写入 NVS 绑定，`generation=1` |
| 重启后重连 | S3 读到 `peer=98c377f6c644 channel=1`，直接进入加密单播，未重新配对 |
| C3 发送 | `sent=1783 captured=1783 send_err=0 retries=0 tx_fail=0` |
| S3 接收 | `rx=1344 dup=0 gap=0 late=0 loss=0 decode_err=0 rejected=0` |
| 主机枚举 | `system_profiler` 报 `MicClicker Microphone`、16 kHz、1 声道、USB 传输 |
| 实际录音 | `ffmpeg -f avfoundation -i ":0"` 录到 10 s 音频；`astats` RMS −46.0 dB、Peak −36.1 dB、Flat factor 0（非恒定值，是真实连续信号） |

C3 侧 1783 帧对 S3 侧 1344 帧的差值不是丢包：两个日志窗口起点不同（S3 先开机），差值等于时间偏移。

### 3.2 自适应缓冲行为

漂移补偿在实测里是可观测的：录制开始后缓冲从预热水位缓慢回落并被控制器拉回。

| 阶段 | `fill_ms` | 说明 |
| :--- | :--- | :--- |
| 主机未开流 | 0 | 端点空闲时不写环形缓冲（否则只会制造假溢出） |
| 开流瞬间 | 62 → 70 | 端点等待缓冲达到 `MIC_JITTER_TARGET_MS=60` 后开始出包 |
| 持续录音 | 26–70 波动 | 高水位 160 ms 触发丢帧、低水位 12 ms 触发复帧；实测 30 min 内未触及任何一侧 |

### 3.3 30 分钟连续录音（2026-11-15）

条件同 3.1。录音 1799.78 s（`ffprobe`），两端串口日志窗口 1679 s（log capture 晚于录音启动，属采集口径差异，非断流）。

`check.sh c3.log s3.log 1800` → **RESULT: PASS**，11 项全过：

| 指标 | 实测 |
| :--- | :--- |
| 发送帧率 | 50.02 fps（83 997 帧 / 1679 s） |
| 采集 / 编码错误 | 0 / 0 |
| 发送失败 | 0 / 83 997（0.000%） |
| 送达率 | 100%（83 997 / 83 997） |
| 端到端速率一致性 | 发送 50.02 vs 接收 50.01 fps（差 0.01） |
| 解码错误 | 0 |
| 有效丢包 | 0 / 89 505 帧（0 ppm） |
| 环形缓冲溢出 | 0 |
| 欠载 | 0 / 89 505（0 ppm） |
| 缓冲水位 | 4–82 ms（容量 200 ms，高水位 160 ms 未触及） |
| 漂移补偿触发 | `repeats=3`、`drops=0`——控制器真实介入且只做了 3 次 1 ms 复帧 |

音频侧：`astats` RMS −53.7 dB、Peak −26.5 dB、Flat factor 0；按每 3 分钟分段测电平均在 −51.7…−55.7 dB，无衰减或抬升；**1799 个 1 秒块中全零块为 0**，即全程没有数字静音段。

> 说明（不要把这条读成漂移已被验证）：`repeats=3 / drops=0` 说明控制器方向正确地补了 3 ms，但**这台 C3 与本 S3 在本次条件下的相对漂移约 3 ms / 1800 s ≈ 0.00017%**，比 `hardware-c3.md` 记录的 0.42% 小三个数量级。两者不矛盾：0.42% 是上一项目另一对晶振的实测值，不是本对板卡的属性。因此本次 30 分钟运行**没有真正压到漂移补偿的稳态路径**——控制器只被触发了 3 次，远不足以验证长时间下的收敛行为。
>
> **这是第 4 阶段最大的未验证项**：要验证漂移补偿的长期行为，需要一个相对漂移明显更大的样本（换板、换温度或人为偏置），否则“30 分钟无溢出无欠载”只能说明这对板卡漂移很小，不能说明控制器在大漂移下也稳。主机侧「快/慢 0.42% 生产端各模拟一小时不发散」是对这一缺口的补充证据，但那是模型而非真机。

## 4. 已知限制（不得据此宣称已全面通过）

- **只测了 macOS**。Windows / Linux 枚举、录音权限、设备选择、热插拔、休眠恢复均未验证。
- **ASR 效果未对比**。目前只证明“能录到真实音频、无持续断流”，没有与同环境有线麦克风做识别率基线比较，也没有测端到端延迟分解（无线/缓冲/USB）。
- **只测了 1 米直视、信道 1、无干扰**。距离、穿墙、2.4 GHz 拥塞、多 AP 环境均未测。
- **按键链路未接入产品固件**。S3 的 `audio_link.c` 把 KEY 帧计为 `rejected`：第 5 阶段才把按键、ACK、去重、all-keys-up 与音频并发起来。
- **漂移补偿的长期行为未在真机验证**。本对板卡实测漂移仅约 0.00017%，30 分钟只触发 3 次补偿，没有压到稳态路径。见 3.3 的说明。
- **配对仍是明文交接**。与第 3 阶段同样的安全边界：配对窗口内 LMK 明文广播，无防中间人。见 [protocol.md](../../../docs/protocol.md) 3.5。
- **G.722 ITU 官方向量仍未验证**（需 ITU 账号）。与 ffmpeg 逐比特一致不等价于通过 ITU 一致性测试。
- **单板验证边界**：本次为同一块 C3、同一块 S3。换板后需重测配对与电平。

## 5. 复现步骤

```bash
# 1) 构建（仓库根目录）
./firmware/build.sh s3
./firmware/build.sh c3

# 2) 烧录（端口按实际枚举替换）
idf.py -C firmware/s3 -B firmware/s3/build -p /dev/cu.usbmodemXXXX flash
idf.py -C firmware/c3 -B firmware/c3/build -p /dev/cu.usbmodemYYYY flash

# 3) 先开机 S3（未绑定时常驻等配对），再开机 C3（作为发起方配对）
#    已配对时两端顺序无关

# 4) 抓两端日志
python3 -c "import serial,time; s=serial.Serial('/dev/cu.usbmodemXXXX',115200);
f=open('s3.log','wb');
[f.write(d) or f.flush() for d in iter(lambda: s.read(4096), b'') if d]" &

# 5) 录音 30 分钟
ffmpeg -y -f avfoundation -i ":0" -t 1800 -ar 16000 -ac 1 -c:a pcm_s16le rec30min.wav

# 6) 判分
./firmware/tests/audio_link/check.sh c3.log s3.log 1800
```

## 6. 主机侧组件测试

缓冲与漂移控制器不依赖硬件，单独可测：

```bash
./firmware/tests/audio_jitter/run.sh
```

覆盖：无数据时的静音与欠载计数、字节级顺序往返、拒绝非整毫秒、溢出丢最旧、**快 0.42% 生产端按模拟一小时不发散**、**慢 0.42% 生产端不长期干涸**、遮蔽衰减、flush 保留计数器。
